# WT - LlamaFarm Worktree Manager

## Overview

`wt` is a Bash utility for managing multiple concurrent LlamaFarm development environments using git worktrees. It enables parallel agent coding sessions without port conflicts or service collisions.

**Key Features:**
- Hash-based port assignment (no collisions)
- Per-worktree service isolation
- CLI wrapper with automatic server URL routing
- `.localhost` hostname addressing (zero config)

## CLI Design

### Worktree Management

| Command | Description |
|---------|-------------|
| `wt create <name>` | Create worktree, install deps, build, cd into it |
| `wt list` | List all worktrees with status, ports, URLs |
| `wt delete [name]` | Stop services, remove worktree, clean up |
| `wt switch <name>` | cd into worktree directory |
| `wt switch` | Interactive worktree picker, then cd |
| `wt status [name]` | Show detailed status of worktree(s) |

**Context Detection:** Current worktree is detected from `$PWD`. If you're inside a worktree directory, commands automatically use that worktree.

**`wt create` runs these steps:**
1. Create git worktree with new branch
2. Generate `.env.wt` with port assignments
3. Run `wt install` (parallel dependency installation)
4. Run `wt build` (build CLI + services)
5. `cd` into the new worktree directory

### Service Lifecycle

| Command | Description |
|---------|-------------|
| `wt start [name]` | Start all services for worktree |
| `wt stop [name]` | Stop all services for worktree |
| `wt restart [name]` | Restart all services |
| `wt logs [name] [service]` | Tail logs (server\|rag\|runtime\|designer) |

### Build & Install

| Command | Description |
|---------|-------------|
| `wt install [name]` | Install all dependencies |
| `wt build [name]` | Build services + CLI with correct server URL |

### CLI Wrapper

| Command | Description |
|---------|-------------|
| `wt lf [name] <args>` | Run `lf` CLI targeting worktree's server |
| `wt lf chat "hello"` | Chat with current worktree's server |

### Utilities

| Command | Description |
|---------|-------------|
| `wt url [name]` | Print service URLs |
| `wt open [name]` | Open Designer in browser |
| `wt health [name]` | Check health of all services |
| `wt prune` | Remove worktrees for merged branches |

## Technical Design

### Worktree Location

**Directory Structure:**
```
~/worktrees/llamafarm/           # Configurable via WT_ROOT
├── main/                        # Main branch (optional)
├── feat-rag-visibility/         # Feature worktree
├── fix-auth-bug/                # Another worktree
└── .wt/                         # Metadata directory
    ├── config                   # Global wt config
    └── ports.json               # Port assignments registry
```

**Naming Convention:**
- Branch `feat/rag-visibility` → directory `feat-rag-visibility`
- Slashes replaced with hyphens for filesystem compatibility

### Port Assignment Strategy

**Base Ports:**
- Server: 8000
- Designer: 5173
- Universal Runtime: 11540
- Celery: filesystem broker (no port needed)

**Hash-based Port Allocation:**
```bash
# CRC32 hash of worktree name, modulo 900, plus offset of 100
# This gives range 100-999, avoiding conflicts with base ports
offset=$(echo -n "$worktree_name" | cksum | cut -d' ' -f1)
offset=$((offset % 900 + 100))

server_port=$((8000 + offset))      # Range: 8100-8999
designer_port=$((5000 + offset))    # Range: 5100-5999
runtime_port=$((11000 + offset))    # Range: 11100-11999
```

**Example Assignments:**
| Worktree | Offset | Server | Designer | Runtime |
|----------|--------|--------|----------|---------|
| `main` | 0 (reserved) | 8000 | 5173 | 11540 |
| `feat-rag-visibility` | 423 | 8423 | 5423 | 11423 |
| `fix-auth-bug` | 187 | 8187 | 5187 | 11187 |

**Collision Handling:**
- Store assignments in `~/.wt/ports.json`
- On collision, increment offset until unique
- Release ports when worktree deleted

### Hostname-based Addressing

Uses `.localhost` TLD which works out of the box on macOS (no setup required):

**URL Convention:**
```
http://server.feat-rag.localhost:8423
http://designer.feat-rag.localhost:5423
http://runtime.feat-rag.localhost:11423
```

**How it works:**
- `*.localhost` resolves to `127.0.0.1` automatically on macOS
- No `/etc/hosts` entries needed, no dnsmasq, no sudo
- Port is still required in the URL

**Name Sanitization:**
- Branch `feat/rag-visibility` → hostname component `feat-rag-visibility`
- Slashes become hyphens for DNS compatibility

### Environment Configuration

Each worktree gets an auto-generated `.env.wt` file:

```bash
# Auto-generated by wt for worktree: feat-rag-visibility
# DO NOT EDIT - regenerate with: wt install

# Worktree Identity
WT_NAME=feat-rag-visibility
WT_ROOT=/Users/bobby/worktrees/llamafarm
WT_PATH=/Users/bobby/worktrees/llamafarm/feat-rag-visibility

# Port Assignments
LF_SERVER_PORT=8423
LF_SERVER_HOST=0.0.0.0
LF_DESIGNER_PORT=5423
LF_RUNTIME_PORT=11423
LF_RUNTIME_HOST=127.0.0.1

# Service URLs (for inter-service communication)
LF_SERVER_URL=http://localhost:8423
LF_RUNTIME_URL=http://127.0.0.1:11423

# Data Isolation
LF_DATA_DIR=~/.llamafarm/worktrees/feat-rag-visibility

# Celery Configuration (filesystem broker, isolated per worktree)
CELERY_BROKER_URL=filesystem://
CELERY_BROKER_FOLDER=~/.llamafarm/worktrees/feat-rag-visibility/broker

# Designer API URL
VITE_APP_API_URL=http://localhost:8423
```

**Loading the Environment:**
- Services source `.env.wt` on startup
- `wt start` ensures env is loaded before launching
- `wt shell` exports env into new shell session

### CLI Wrapper Implementation

The `wt lf` command wraps the LlamaFarm CLI:

```bash
wt lf [worktree] <command> [args...]

# Examples:
wt lf chat "hello"              # Uses current worktree's server
wt lf feat-rag chat "hello"     # Explicit worktree
wt lf --help                    # Pass-through to lf --help
```

**Implementation:**
```bash
wt_lf() {
    local wt_name=$(wt_detect_current)  # Auto-detect from cwd
    local server_url=$(wt_get_server_url "$wt_name")

    # Run lf with correct server URL
    "$WT_ROOT/$wt_name/dist/lf" --server-url "$server_url" "$@"
}
```

### Dependencies Installation

| Subsystem | Directory | Install Command | Notes |
|-----------|-----------|-----------------|-------|
| CLI | `cli/` | `go mod download` | Then `go build` |
| Server | `server/` | `uv sync` | Python 3.12+ |
| RAG | `rag/` | `uv sync` | Python 3.11+ |
| Runtime | `runtimes/universal/` | `uv sync --extra classification --extra anomaly --extra document` | Heavy deps |
| Designer | `designer/` | `npm install` | Node.js |

**Parallel Installation:**
```bash
wt_install() {
    echo "Installing dependencies for $wt_name..."

    # Run in parallel with progress indicators
    (cd "$wt_path/cli" && go mod download) &
    (cd "$wt_path/server" && uv sync) &
    (cd "$wt_path/rag" && uv sync) &
    (cd "$wt_path/runtimes/universal" && uv sync --extra classification --extra anomaly --extra document) &
    (cd "$wt_path/designer" && npm install) &

    wait
    echo "Dependencies installed."
}
```

### Service Management

**Starting Services:**
```bash
wt_start() {
    local wt_name="$1"
    source "$wt_path/.env.wt"

    # Check ports are available
    wt_check_ports "$wt_name" || return 1

    # Start in dependency order: server → runtime → rag → designer
    wt_start_server "$wt_name"
    wt_start_runtime "$wt_name"
    wt_start_rag "$wt_name"
    wt_start_designer "$wt_name"
}
```

**Process Management:**
- PID files stored in `~/.llamafarm/worktrees/<name>/pids/`
- `wt stop` sends SIGTERM, waits, then SIGKILL if needed
- `wt status` checks PID files and port availability
- Lock file prevents concurrent `wt start` on same worktree

## Additional Features

### Conflict Prevention
- Port availability check before starting (`lsof -i :<port>`)
- Lock file at `~/.llamafarm/worktrees/<name>/.lock`
- Warn if another worktree is using requested ports

### Directory-based Context

The `wt` command detects the current worktree from your working directory:

**Context Resolution:**
1. Explicit `<name>` argument (if provided)
2. Auto-detect from `$PWD` (check if inside a worktree)
3. Error: "Not in a worktree. Run `wt switch <name>` or `wt list`"

**Example Workflow:**
```bash
wt create feat/auth-refactor  # Creates, installs, builds, then cd's into it
pwd                           # → ~/worktrees/llamafarm/feat-auth-refactor
wt start                      # Starts services (detected from cwd)
wt lf chat "hello"            # Uses this worktree's server
wt logs server                # Tails server logs

wt switch fix-bug             # cd into fix-bug worktree
pwd                           # → ~/worktrees/llamafarm/fix-bug
wt start                      # Now starts fix-bug's services
```

**Shell Function Requirement:**
Since `cd` can't change the parent shell's directory from a script, `wt switch` and `wt create` need to be shell functions. Users add this to `.bashrc`/`.zshrc`:

```bash
# Add to ~/.bashrc or ~/.zshrc
wt() {
    if [[ "$1" == "switch" || "$1" == "create" ]]; then
        local target_dir
        target_dir=$(/path/to/wt-script "$@" --print-dir)
        if [[ -n "$target_dir" && -d "$target_dir" ]]; then
            cd "$target_dir"
        fi
    else
        /path/to/wt-script "$@"
    fi
}
```

### IDE Integration
- `wt vscode <name>` - Open worktree in VS Code
- Generates `.vscode/settings.json` with correct paths
- Sets Python interpreter, Go paths

### Cleanup & Maintenance
- `wt prune` - List/remove worktrees for merged branches
- `wt gc` - Clean up orphaned data directories
- `wt doctor` - Diagnose common issues (ports, deps, etc.)
